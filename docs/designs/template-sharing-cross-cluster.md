# br0kr — Template Reachability, Logical Instances, and Requested Replication
## Converged design (paper run, 2026-07-10; rev 2 post-critique 2026-07-11) — targets migrations 0031+, main @ ba3bc12

---

## 1. Problem and hard invariants

### 1.1 The problem

An agent calls `request_lease(template=T)` and br0kr must place a cloned VM on **some node** — intra-cluster or cross-cluster — cloning from a copy of T that the **target node can actually reach**, onto a **storage that node can reach**, with correct quota and the per-cluster vmid fence intact.

Today this is broken in four compounding ways:

1. **A template is one `(cluster_id, vmid)` pin** (0012). Admission checks only cluster equality (`template_not_on_cluster`, admission.py:499-513) — never node- or storage-level reachability, and never which node *hosts* the template's config.
2. **The physical clone target is one global env**, `BR0KR_VM_CLONE_STORAGE`, passed verbatim to `qm clone --storage` for every node and cluster (daemon.py:1122 → reconciler.py:137 → pve.py:405). This caused a **real cross-provision**: a lease aimed at node-b cloned onto node-a-local FastStorage.
3. **The `storage` table is a node-agnostic quota bucket** (`{id, total_gb}`, 0001:50-53). `lease.storage_id` debits it; it never chooses physical placement. Quota identity and physical placement are two disconnected axes joined only by operator convention.
4. **The scheduler is blind** to both (scheduler.py:48-57 hard-codes "storage is global"), and the failure modes are silent: an unroutable or misplaced lease is at best an operator-log line; the agent sees nothing.

The storage reality: "FastStorage" is *declared* cluster-wide in PVE but *physically* node-a-local. "OMV" is a true all-node NFS mount. Reachability is a per-`(node, storage)` fact br0kr models nowhere.

### 1.2 Hard invariants (preserved, not weakened)

| # | Invariant |
|---|---|
| I1 | `admit()` is the **sole admission authority**: ordered `pg_advisory_xact_lock` per debited scope (single lexicographic sort of key strings, READ COMMITTED, non-autocommit), derived capacity (never a stored counter), guarded-CAS lifecycle. The closed double-allocation proof must not reopen. |
| I2 | **Per-VMID fence** (`br0kr-lease-<id>`) + **per-cluster vmid uniqueness** (0004 partial index; `cluster_id`+`vmid` stamped in one CAS at `begin_provisioning`). Cross-cluster vmid number collisions stay legal. |
| I3 | **Storage quota debit stays correct**: `_STORAGE_AVAIL` = `total_gb − Σ req_disk_gb` over the shared `CAPACITY_STATES`; existing lease debits survive any migration untouched. |
| I4 | **No-orphan**: every provisioned guest is tracked by a lease (or a job ledger row) and reclaimable from **both directions** (ledger-driven reclaim + fleet-side sweep with positive evidence). |
| I5 | Scope-key **strings are lock identity** shared across gateway/mcp/dashboard/daemon: `node:{id}` / `storage:{id}` / `project:{id}` are never reformatted. `daemon._queue_block_keys` changes only in lockstep with any grammar change (this design makes **no** grammar change). |
| I6 | Idempotency: the agent-visible ask (`template_id`, caller `storage_id`, node/cluster, req_*) keeps its `_same_ask` identity; broker-resolved placement lives **below** the idem-key surface. |
| I7 | MCP contract: dict-not-raise; machine-usable snake_case reason codes; every new code classified queueable-vs-hard against `QUEUEABLE_REJECTS`. |

**Acceptable sacrifice (must be explicit, never silent):** a template is only cloneable where a copy physically exists. "Not available here" is a *structured refusal or a bounded queue wait* — never a silent cross-provision, never a substitution. **Rev-2 tightening:** even a *maliciously-plausible* wrong operator declaration must not produce a silently-ACTIVE wrong-pool lease — the post-clone placement assertion (§4.3, §5.3) is now a **mandatory shipped control**, not a deferred checklist item; the worst residual is a transient wrong-pool write that is detected, destroyed, audited, and quarantines the offending declaration.

## 2. Recommended approach and justification

### 2.1 Recommendation

**A hardened version of the middle approach**: *logical template + physical `template_instance` rows, operator-declared reachability as config-as-data with a verified/quarantined pair lifecycle and a runtime placement assertion, and an explicitly-REQUESTED replication job* (template_build-shaped, never PDM) — with every confirmed adversarial mitigation folded in, and the build **re-sequenced so the cross-provision bug dies two PRs before any replication machinery exists**.

Explicitly **rejected**:

- **Lease-time auto-replication** (approach 3's headline). The adversarial run showed it converts one agent's opt-in wait into fleet-wide FIFO damage and dishonest states:
  - *Parked waiters head-block the strict per-scope FIFO* for entire copy wall-times (`daemon._promote` holds `project:`/`cluster:*` lanes for any non-exempt reason) — an involuntary multi-minute wait for every scope-sharing ask.
  - *Parking into a disabled data plane*: `auto_replicate` (hot knob, gateway) × `BR0KR_REPLICATE_LIMIT=0` (env, daemon) parks leases behind jobs that never advance; agents are told "a copy is coming" and die at `queue_timeout`.
  - *Unfulfillable promises*: without a hosting-node model, a completed copy can still yield zero placeable candidates — the copy runs, the waiter times out anyway.

  A **level-triggered waiter coupling** (§5.4) makes queue-behind-an-*existing* job safe; *spawning* jobs from lease asks is deferred until that coupling is proven live.

- **Probe-granted reachability** (approach 3's discovery). The **critical** finding: `GET /nodes/{n}/storage` reports *name-level* availability — a cluster-declared dir storage shows `active=1` on every node because PVE auto-creates the path. A probe that *grants* placement silently resurrects the exact motivating bug **with an audit trail asserting correctness**. Probes in this arc obey a pre-committed contract: *reads may only NARROW (mark unreachable / flag drift / quarantine), never widen* — `verify_declarations` (§4.7) is exactly that shape and ships in this arc; widening discovery stays a future arc. §11 carries the ACL prerequisite (`Datastore.Audit` on `/storage`) and probe checklist.

- **Refuse-only with no logical identity** (approach 1). Three wounds are structural, not patchable:
  - The **template-less path** (`BR0KR_VM_DISK` create-blank, `BR0KR_VM_TEMPLATE` env clone) reproduced the bug through a door that design left open "for docs to cover" — and its own claim *"over-declaration surfaces as a loud PVE error"* is **false** for dir-type storage (PVE mkpaths and allocates locally, silently).
  - One-catalog-row-per-physical-copy leaks **private template existence** through name-matched `alternatives`, and fragments governance (per-row grants).
  - Hand-staging as the *only* cross-cluster path systematically reopens the untagged-template permanent-orphan class (a clone of an unmarked template is invisible to every reclaim).

  Its good parts — declared reachability schema, clean structured refusals, per-candidate decision traces, the env retirement, the deploy-sequencing discipline, and (rev 2) its `verify_declarations` reconciliation verb and runbook standing rule — are all absorbed here.

### 2.2 Why the middle approach survives (with repairs)

Every **critical/high** attack on it has a bounded, in-pattern fix, each adopted below:

| Attack (severity) | Fix adopted (section) |
|---|---|
| Sweeper destroys READY/converted instances via "job terminal ⇒ reclaim" (**critical**) | Repl-fence destroy evidence = job `FAILED` **only**; READY-with-fence = idempotent finalize-retry; sweep-path destroyer refuses `template=1`; absent job row = spare + warn (§6.6) |
| Missing hosting-node dimension — PVE clones must be POSTed at the config-owning node (**critical**) | `template_instance.node_id`; `usable(I,N)` requires `N == I.node_id` until cross-node clone is live-verified (§4.1) |
| **Silent wrong-pool landing via over-declared reachability on dir-type storage** (**critical-class residual, rev 2**) | Mandatory **post-clone disk-location assertion** on every clone path (lease + replication), default-on, audited break-glass only (§4.3, §5.3); `storage_node` pairs carry a **verified/quarantined lifecycle** — assertion failure quarantines the pair fail-closed (§3.1) |
| Replication reservation lease is reap-bait (no heartbeat) (**high**) | Reservation heartbeated every progress poll + lapse-abort, TTL ≥ 2× stale cutoff — the migration saga's own doctrine, copied *completely*, with the reservation's **exact column shape reused from the `br0kr-mig-` reservation** (§5.3) |
| NULL-storage grandfather fail-open re-arms the bug on node-add (**high**) | Unbound instances usable **only** in single-node clusters; `register_node` **refuses** joining a second node while unbound READY instances exist (`cluster_has_unbound_instances`) (§4.1, §3.2) |
| Held-ADMITTED leases head-block the capped work list + audit flood (**high**) | Held leases excluded from `list_admitted` hot path; edge-triggered log/audit writes; bounded auto-release (§4.3, §7) |
| Instance immortality / no rotation (stale content forever) (**high**) | `RETIRED` state excluded from uniqueness + usability; rows kept for FK history; retire/force-delete verbs with in-use guards (§3.2, §4.4) |
| Storage-row aliasing double-sells physical bytes (**high**) | `UNIQUE (cluster_id, COALESCE(pve_name, id))` partial index + `duplicate_pve_storage` refusal (§3.1) |
| Debit≠placement silent redirect (**high**) | If the ask names a bound quota row, that row's `pve_name` **is** the physical target or the ask **refuses** — never a silent fallback (§4.2) |
| Legacy env paths (`VM_TEMPLATE`/`VM_DISK`) bypass the model (**high**) | Both fail-closed the moment >1 node or >1 cluster is served (§4.5) |
| Migration bricking on `(cluster,vmid)` catalog aliases (**high**) | 0004-style DO-block pre-check; aliases become **one instance row per template row sharing the guest**, with an explicit shared-guest refcount guard on every physical verb (§3.2, §4.4) |
| Waiter stranding (job dies, ask times out as `queue_timeout`) (**high**) | Level-triggered waiter sweep with honest terminal reasons (§5.4, §7) |
| **Cluster decommissioning permanently FK-blocked by immortal replication rows** (**high, rev 2**) | `guest_settled_at` custody stamp + `prune_replications` retention verb (0024 pattern) + explicit `delete_cluster` decommission recipe (§3.4, §4.4) |
| **Rebuild of a hand-modified built template silently diverges content** (**high, rev 2**) | `template.source_dirty` attestation flag + `mark_template_source_dirty` verb; `rebuild_source` refuses `source_hand_modified`; scenario named as the qemu-guest-agent hand-fix case (§5.2, §10.7) |
| **Silent declaration rot with no reconciliation** (**high, rev 2**) | `verify_declarations` narrow-only admin verb in this arc + runbook standing rule; graceful degradation when the ACL is absent (§4.7) |

## 3. Data model / schema changes

All additive; new numbered files only; every FK is `NO ACTION` unless stated (fail-closed doctrine, per 0013). No scope-key string changes anywhere.

### 3.1 `0031_storage_placement.sql`

```sql
ALTER TABLE storage ADD COLUMN IF NOT EXISTS cluster_id text REFERENCES cluster(id);  -- NO ACTION
ALTER TABLE storage ADD COLUMN IF NOT EXISTS pve_name  text;  -- physical PVE storage name; effective = COALESCE(pve_name, id)

CREATE TABLE storage_node (
  storage_id     text NOT NULL REFERENCES storage(id) ON DELETE CASCADE,
  node_id        text NOT NULL REFERENCES node(id)    ON DELETE CASCADE,
  verified_at    timestamptz,          -- set by the first PASSING post-clone placement assertion over this pair
  quarantined_at timestamptz,          -- set by a FAILING assertion or verify_declarations hard evidence; fail-closed
  PRIMARY KEY (storage_id, node_id)
);

-- One quota row per physical pool per cluster (closes the aliasing double-sell):
CREATE UNIQUE INDEX storage_pool_uniq ON storage (cluster_id, COALESCE(pve_name, id))
  WHERE cluster_id IS NOT NULL;
```

Design decisions:

- **The `storage_node` junction is the single source of truth for reachability.** There is **no** `shared` boolean in the predicate: "shared" is only a dashboard convenience that *expands into junction rows at declaration time*. Node-add is therefore naturally fail-closed — a new node reaches nothing until rows are written (kills the "shared=true silently extends to new members" attack).
- **Pair lifecycle (rev 2, replaces the vague "declare-time warning for suspicious rows"):** every junction row is born **unverified** (`verified_at` NULL). Unverified pairs are placeable (else bootstrap deadlocks) but are surfaced as a standing `unverified_reachability_pairs` fleet stat, a warning in the `set_storage_nodes`/declare response (`verified:false`), and a boot-log line. The **first passing post-clone disk-location assertion** (§4.3) over the pair stamps `verified_at`. A **failing** assertion stamps `quarantined_at`: `reach()` requires `quarantined_at IS NULL`, so a quarantined pair is unreachable until an operator explicitly clears it (`clear_storage_node_quarantine`, audited). Quarantine is narrowing-only and therefore consistent with the no-widening probe contract. This is the concrete mechanism; no heuristic hand-waving remains.
- `pve_name` is an **explicit mapping** (open question from research resolved): the quota id is never assumed to be a PVE name. New `valid_pve_storage` charset validator mirrors `valid_pve_node`.
- **Data-driven backfill, no site names in the migration**: iff exactly ONE cluster row exists, bind every storage row to it and insert `storage_node` rows for every node of that cluster (`verified_at` backfilled to `now()` for the single-node cluster — those pairs are proven by the entire live history). On the deploy host (one cluster, one node) this is byte-identical to today's semantics. Multi-cluster DBs stay unbound and are loudly flagged. `pve_name` backfills to `id`, flagged `backfilled` in the boot log until operator-confirmed.
- A one-physical-pool-mounted-by-two-clusters case must be **two rows** whose `total_gb` the operator splits so the sum equals the physical size — documented in the runbook as an explicit sacrifice (§10).
- `delete_storage` gains refusals for **every** new reference: `storage_has_templates` (instances), `storage_is_clone_target` (non-terminal `lease.clone_storage_id`), `storage_has_builds`/`storage_has_replications` (in-flight jobs); `force=True` severs **terminal** lease history for *both* `storage_id` and `clone_storage_id` (closes the "force-delete FK-aborts forever" attack).

### 3.2 `0032_template_instances.sql`

```sql
CREATE TABLE template_instance (
  id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  template_id    text   NOT NULL REFERENCES template(id),        -- NO ACTION (0013 rationale extended)
  cluster_id     text   NOT NULL REFERENCES cluster(id),         -- NO ACTION (deliberately not 0012's CASCADE)
  node_id        text   REFERENCES node(id) ON DELETE SET NULL,  -- the PVE node OWNING the vmid's config
  vmid           int    CHECK (vmid > 0),                        -- nullable: REPLICATING rows pre-mint have none
  storage_id     text   REFERENCES storage(id),                  -- quota row whose pve_name the disk lives on
  instance_state text   NOT NULL DEFAULT 'READY'
                 CHECK (instance_state IN ('REPLICATING','READY','RETIRED','FAILED')),
  origin         text   NOT NULL DEFAULT 'seed'
                 CHECK (origin IN ('seed','build','replication','manual')),
  replication_id bigint,          -- provenance link, no FK (audit-style)
  size_gb        bigint,
  created_at     timestamptz NOT NULL DEFAULT now(),
  CHECK (instance_state <> 'READY' OR vmid IS NOT NULL)          -- READY always has a guest
);

-- one live copy per (template, cluster, pool); RETIRED/FAILED excluded so rotation is possible:
CREATE UNIQUE INDEX template_instance_live_uniq ON template_instance (template_id, cluster_id, storage_id)
  WHERE instance_state IN ('REPLICATING','READY') AND storage_id IS NOT NULL;
CREATE UNIQUE INDEX template_instance_unbound_uniq ON template_instance (template_id, cluster_id)
  WHERE instance_state IN ('REPLICATING','READY') AND storage_id IS NULL;
-- per-template physical fact; transient-guest cross-vmid protection lives on the job table (3.4):
CREATE UNIQUE INDEX template_instance_cluster_vmid ON template_instance (template_id, cluster_id, vmid)
  WHERE vmid IS NOT NULL AND instance_state IN ('REPLICATING','READY');
```

- **Alias backfill, resolved precisely (rev 2 — the earlier "aliases share one instance row" wording was unrepresentable, since `template_id` is a single NOT NULL FK):** the backfill creates **one instance row per template catalog row**. Two catalog rows aliasing one `(cluster_id, vmid)` (e.g. `debian12` and a hypothetical `debian12-ga` both → lab1/9900) yield **two instance rows sharing one physical guest** — legal under the per-template partial index `template_instance_cluster_vmid`, and semantically correct: the guest is one physical fact serving two logical identities. A 0004-style `DO`-block pre-check still runs, but as a **named-offender report**, not an abort — the deploy never bricks. Rehearse 0031-0034 against a `pg_dump` of the live the deploy host ledger before deploying (deploy-runbook step).
- **Shared-guest discipline (rev 2):** because N instance rows may share one `(cluster_id, vmid)`, every verb that touches the *physical* guest is refcounted across templates:
  - `destroy_instance_guest(I)` refuses `guest_shared` while any **other** live (REPLICATING/READY) instance row — any `template_id` — holds the same `(cluster_id, vmid)`. Retire/delete the co-tenants first (logical ops, guest untouched).
  - The **drift-repair auto-RETIRE** (§4.4) on clone-source-gone flips **all** live instance rows on that `(cluster_id, vmid)` in one pass — the missing guest is one shared fact.
  - `delete_template(force)` and `delete_template_instance(force)` never touch the guest; only the explicit destroy verb does, and it carries the guard.
  - Fence/sweep logic is keyed on vmid and is unaffected.
- Seeds backfill with `node_id`/`storage_id` **NULL**. **Structural gate replacing the runbook-only guard**: an unbound instance is usable *only* in a cluster with exactly one served node, and `register_node` **refuses** (`cluster_has_unbound_instances`) to add a second node to a cluster holding unbound READY instances. Safe-by-construction on today's the deploy host; impossible to fumble on node-b day.
- `template.cluster_id`/`vmid` are kept frozen (read-compat); `set_template` edits to them are **refused** with a pointer to the instance verbs, and the dashboard editor drops those fields in the same commit (kills the "plausible dead control" drift attack).
- `ALTER TABLE template ADD COLUMN source_url text, ADD COLUMN source_sha256 text, ADD COLUMN source_dirty boolean NOT NULL DEFAULT false` — replication provenance plus the **hand-modification attestation flag** (rev 2, §5.2). Provenance backfilled from `template_build` READY rows; **`build.mark_ready`'s CTE is extended to stamp them forward** (and reset `source_dirty=false` — a fresh build supersedes any hand fix) so post-deploy builds stay replicable (kills the one-shot-backfill decay attack). NULL provenance = not rebuild-replicable (debian12/9900).

### 3.3 `0033_lease_placement.sql`

```sql
ALTER TABLE lease ADD COLUMN template_instance_id bigint REFERENCES template_instance(id); -- NO ACTION
ALTER TABLE lease ADD COLUMN clone_storage_id     text   REFERENCES storage(id);          -- NO ACTION
ALTER TABLE lease ADD COLUMN hold_reason          text;   -- daemon-written diagnostic, not a state
ALTER TABLE lease ADD COLUMN awaiting_replication_id bigint REFERENCES template_replication(id); -- (added by 0034's PR; listed here for coherence)
```

- `template_instance_id` + `clone_storage_id` are stamped **inside** `admit()`'s existing `_INSERT` / promote's CAS (0019 same-statement pattern), are **excluded** from `_LOOKUP`/`_same_ask` (I6), and get `_FK_REASON` entries (`unknown_template_instance`, `no_reachable_clone_storage`).
- **Backfill**: non-terminal templated leases get `template_instance_id` = their cluster's seed instance for their catalog row (deterministic after 0032's per-row backfill — kills the stranded-in-flight-lease upgrade attack). `list_admitted`'s LEFT JOIN moves to the instance (one query, resolving instance vmid + storage `pve_name`).
- **NULL `clone_storage_id` at provision time (rev 2, the pre-PR-2 legacy window, specified in one rule):** a templated lease whose `clone_storage_id` is NULL when the daemon picks it up is **never legacy-provisioned and never held for that reason alone** — the daemon **re-runs the deterministic clone-storage resolution (§4.2), which is a pure function of ledger state, and late-stamps the result** via a guarded `UPDATE … WHERE id=%s AND state='ADMITTED' AND clone_storage_id IS NULL` before the full-predicate re-check. If resolution refuses (no valid target), the lease holds with `hold_reason='placement_unresolvable'` under the standard held-lease hygiene. Purity of the resolution function is exactly what makes the late stamp safe and idempotent across retries.
- `hold_reason` is written by a guarded `UPDATE … WHERE id=%s AND state IN ('ADMITTED','PENDING')` (widened to PENDING so promote-time refusals are annotatable), **cleared inside `begin_provisioning`'s existing CAS**, and **preserved on terminal rows** (folded into terminal reasons, §7). No new lease state; 0004 and the 0017 CHECK are untouched.

### 3.4 `0034_template_replication.sql`

```sql
CREATE TABLE template_replication (
  id                 bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  template_id        text   NOT NULL REFERENCES template(id),
  source_instance_id bigint REFERENCES template_instance(id),
  target_cluster_id  text   NOT NULL REFERENCES cluster(id),
  target_storage_id  text   NOT NULL REFERENCES storage(id),
  target_node_id     text   REFERENCES node(id) ON DELETE SET NULL,
  vmid               int,                              -- stamped WITH node_id in one CAS (0029 prong 2)
  mechanism          text   NOT NULL CHECK (mechanism IN ('clone_shared','rebuild_source')),
  upid               text,                             -- write-once; re-attach on resume (S07)
  job_state          text   NOT NULL DEFAULT 'REQUESTED'
                     CHECK (job_state IN ('REQUESTED','COPYING','CONVERTING','READY','FAILED','RECLAIMING')),
  attempts           int    NOT NULL DEFAULT 0,
  error              text,                             -- ALWAYS pre-redacted before store (§7)
  requested_by       text   NOT NULL,
  project_id         text   REFERENCES project(id),    -- NULL = operator (quota-exempt); set = tenant
  size_gb            bigint,
  guest_settled_at   timestamptz,                      -- custody of the transient guest provably ended (rev 2)
  created_at         timestamptz NOT NULL DEFAULT now(),
  updated_at         timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX replication_one_active ON template_replication (template_id, target_cluster_id, target_storage_id)
  WHERE job_state IN ('REQUESTED','COPYING','CONVERTING','RECLAIMING');
CREATE UNIQUE INDEX replication_cluster_vmid ON template_replication (target_cluster_id, vmid)
  WHERE vmid IS NOT NULL AND job_state IN ('COPYING','CONVERTING','RECLAIMING');
```

- **No `pdm_move` mechanism, ever, in this table's shape** — the adversarial run showed the two-guest saga is unrepresentable in one `(vmid, node_id, upid)` slot; if a PDM path is ever wanted it gets its own migration and confirm-landed machinery. Sacrifice, stated (§10).
- `node_id` FKs are `ON DELETE SET NULL` on this table and on `template_instance` so node decommissioning is never FK-blocked (delete_node/delete_cluster pre-checks extended with crisp `*_in_use` reasons for the new tables).
- **`guest_settled_at` (rev 2):** stamped in the same CTE whenever the job's custody of a transient guest provably ends — reclaim-confirmed destroy; `fence_mismatch`-as-settled; the vmid-NULL FAILED branch; and, for READY jobs, the moment the fence strip is **confirmed** (finalize or finalize-retry — the guest lives on as a catalog template owned by the instance row, no longer the job's). This is the precondition for retention (below) and reconciles pruning with the sweep's absent-row doctrine: a pruned job cannot leave a live `br0kr-repl-` fence behind, by construction.
- **Retention / decommissioning (rev 2, closes the immortal-FK-web attack):** new operator verb `prune_replications(older_than_days, cluster_id=None)` (the 0024 audit-retention pattern): deletes terminal (`READY`/`FAILED`) jobs with `guest_settled_at IS NOT NULL` and age past the horizon, first severing any terminal leases' `awaiting_replication_id` → NULL (delete_node force pattern; the FK would otherwise abort); refuses (`replication_unsettled`) any candidate without the settle stamp. Breadcrumbs survive in `operator_audit`, so the history is not lost — only the FK anchor. `delete_cluster` gains the full decommission recipe: refuse `cluster_has_replications` (non-terminal jobs) and `cluster_has_instances` (live instances) with crisp reasons; the documented decommission sequence is retire/destroy instances → `delete_template_instance(force)` for the RETIRED/FAILED rows (severs terminal-lease FKs, deletes rows) → `prune_replications(cluster_id=…)` for settled terminal jobs → `delete_cluster`. Every step is a sanctioned verb; no raw SQL ever required. The 0012 `template.cluster_id` CASCADE interaction is explicitly covered: `delete_cluster` pre-checks instance rows **before** the cascade can trip their NO ACTION FK, so the existing verb never regresses into a raw FK error.
- Storage reservation is **not a column**: it is a reservation **lease** through `admit()` with deterministic idem key `br0kr-repl-<job_id>` — new reserved prefix beside `MIGRATION_IDEM_PREFIX`, excluded from `list_admitted` from birth, rejected for caller-supplied keys at the gateway (§5.3).

### 3.5 No-DDL items

New `operator_audit` outcome value `'refused'` (0025 has no CHECK by design); hot knobs (`cross_node_clone`, `replication_cooldown_seconds`, and rev 2's `placement_assert` break-glass) as `operator_setting` rows (0021 pattern — **operator_setting, not env**, so all four admitting processes read the same committed value; kills the env-drift-across-containers attack); no `CAPACITY_STATES` change; no `_queue_block_keys` grammar change.

## 4. Placement algorithm

### 4.1 Predicates (one shared SQL fragment, imported by admission, scheduler, and daemon — snapshot and enforcement can never diverge)

```
reach(N, S)   := EXISTS storage_node(S.id, N.id) AND that row's quarantined_at IS NULL
usable(I, N)  := I.instance_state = 'READY'
                 AND I.cluster_id = N.cluster_id
                 AND ( I.node_id = N.id                               -- v1: instance serves ONLY its hosting node
                       OR (setting cross_node_clone = on              -- post-live-validation only
                           AND full_clone AND reach(N, I.storage_id) AND reach(I.node_id, I.storage_id)) )
                 AND ( I.storage_id IS NOT NULL
                       OR single_served_node(I.cluster_id) )          -- unbound seeds: single-node clusters only
```

The `node_id` term is the repair for the **critical** hosting-node finding: a PVE template's config lives on exactly one node and `qm clone` must be POSTed there; v1 never pretends otherwise. The `quarantined_at` term is rev 2's fail-closed teeth for a declaration proven wrong at runtime.

### 4.2 Clone-storage resolution (deterministic pure function of ledger state ⇒ idempotent retries — and the daemon's late stamp for legacy NULL rows — resolve identically)

For candidate node N, instance I, ask storage Q (= `lease.storage_id`, the quota scope):

1. **Linked clone** (`BR0KR_VM_FULL_CLONE=0`): target := I.storage (PVE physics). If Q given and Q ≠ I.storage → refuse `linked_clone_storage_pinned`. Require `reach(N, I.storage)`.
2. **Full clone, Q given**: Q must be cluster-bound to N's cluster and `reach(N, Q)`, and the physical target **is** `Q.pve_name`. If Q is unbound (`cluster_id` NULL — only possible on multi-cluster deploys post-backfill) → refuse `storage_unbound`. **Never redirect the bytes away from the debited row** — this is the quota-coherence rule that closes the debit≠placement hole and makes the dashboard "Storage pool" picker finally *mean* placement.
3. **Full clone, no Q**: target := I.storage (clone stays on the instance's pool; reach is implied by `usable`).
4. `''`→`None` normalization preserved end to end (empty string to PVE is a 400).
5. **Runtime enforcement (rev 2):** the resolved target is not merely stamped — it is **asserted after the clone lands** (§4.3). Resolution decides; the assertion verifies PVE agreed.

Resolved `clone_storage_id` + chosen `template_instance_id` are stamped in `admit()`'s `_INSERT`, below the idem-key surface (I6); legacy NULL rows get the identical resolution late-stamped by the daemon (§3.3).

### 4.3 Two-layer flow (unchanged architecture: snapshot orders, `admit()` decides), plus the post-clone assertion

- **Pinned** (`request_lease(node_id)`): `admit()` evaluates the full triple **under the already-held node advisory lock**, in the template step of the shared locked core (`admission._locked_fit`; at design time the `_TEMPLATE_CLUSTER` slot), fail-closed, debiting nothing new. Deterministic instance pick: prefer instance on the ask storage, then storage-bound over unbound, then lowest id. Reason order: `unknown_template` → `no_reachable_instance` → `storage_unreachable_from_node` → `linked_clone_storage_pinned` / `storage_unbound` → existing capacity shortfalls. `promote_pinned` mirrors **all** of it (the `template_not_on_cluster` re-check precedent).
- **Scheduled** (`schedule_lease`): the scalar template-cluster resolve (scheduler.py:266-289, 352-379) becomes an instance-**set** resolve; `node_headroom`'s WHERE gains the reachability join, so candidates span **every cluster** holding a usable instance — this is where cross-cluster golden-ticket placement happens. `_STORAGE_REJECTS` splits: `unknown_storage`/`insufficient_storage` stay request-definitive; the reachability codes become **per-candidate** (try next node). `ScheduleResult.tried` upgrades to `list[{node_id, reason}]`. `rank_candidates` stays pure over a widened row.
- **Provision** (daemon): before cloning, re-check the **full stamped predicate** — instance exists AND READY, `usable(I, lease.node)`, resolved storage still reachable and (when Q bound) still matching Q's binding (kills the "re-checks one-third of the state" attack); late-stamp resolution first if `clone_storage_id` is NULL (§3.3). Any mismatch: leave ADMITTED, write `hold_reason` (`instance_unavailable` / `placement_reachability_lost` / `cross_provision_refused` / `placement_unresolvable`), **never substitute** — the unroutable-lease discipline (daemon.py:471-491). The clone is issued via the **instance's node driver** (same node as the lease in v1). The daemon also reads the source vmid's tags before the first clone and refuses `template_untagged` (an existing read verb, no probing doctrine violated).
- **Post-clone placement assertion (rev 2 — mandatory, ships with the first gated clone path in PR-2, not deferred):** immediately after the clone lands and the lease fence is stamped (inside the existing configure step, before IP discovery), the daemon **re-reads the guest config via the same config GET `grow_boot_disk` already performs** (zero new API surface, known-working on the deployed PVE), parses the boot disk's volid (`<storage>:...`), and compares the storage name to the stamped `clone_storage`'s effective `pve_name` (linked clones: the instance's pool). **Mismatch** = the over-declaration case PVE handled silently: the guest is released through the existing fenced release path (guest is fenced; no orphan), the lease terminates with `released_reason='cross_provision_detected'`, a distinct audit row + `log.error` + `TickSummary.cross_provision_detected` fire, and the `(lease.node, resolved_storage)` junction row is **quarantined** (`quarantined_at`), turning every subsequent ask over that pair into an up-front refusal. **Match** on a previously-unverified pair stamps `verified_at`. The assertion is default-ON with a single audited break-glass `operator_setting placement_assert=off`; a skip (break-glass or unparseable volid) is logged per-lease, never silent. This closes the last silent-cross-provision path: the worst case is a transient wrong-pool write that is detected, destroyed, audited, and fail-closes the wrong declaration — the hard requirement's "never silently land" is met by runtime evidence, not operator trust.
- **Held-lease hygiene** (kills the head-block + flood attacks): leases with `hold_reason` set are **excluded from `list_admitted`'s hot work list** (mirroring the `node_ids` anti-head-blocking filter) and re-checked on the sweep cadence, hold cleared when the predicate passes; log/audit writes fire on the **hold_reason edge only**; after `N` consecutive blocked re-checks (default: 60) the lease auto-releases with `released_reason='placement_blocked:<hold_reason>'` — no guest exists, so no orphan; capacity frees; the ~68-year-TTL renew loophole is closed.

### 4.4 Instance lifecycle verbs (the missing death story)

- `bind_instance_placement(instance_id, node_id, storage_id, size_gb)` — the seed-backfill verb. **Full validation:** storage cluster == instance cluster; `reach(node, storage)`; `size_gb` **REQUIRED** (>0) — binding a seed simultaneously cures its unbound status and its unsized status (§5.3); **required before node-b joins** (enforced by the `register_node` gate).
- `register_template_instance(template_id, cluster_id, node_id, storage_id, vmid, size_gb, origin='manual')` — the manual/cross-cluster registration verb, now specified to the same standard (rev 2): `node_id`, `storage_id`, `vmid`, `size_gb` are **all REQUIRED** (manual rows can never be unbound or unsized — NULLs would re-open the unbound-instance class through the side door); validations: storage bound to the named cluster, `reach(node_id, storage_id)`, `vmid > 0`, uniqueness via the three partial indexes (crisp `instance_exists` refusal); and a **registration-time read-only config GET on the owner node** requiring `template=1` AND `TEMPLATE_TAG` present, else refuse `guest_not_template` / `template_untagged` — the same read class the daemon's pre-clone check uses, so the untagged-orphan class is caught at registration AND at clone #1, and a hand-staged row can never enter the catalog unfenced-by-convention.
- `retire_instance(instance_id)` — READY→RETIRED; **refuses `instance_in_use` while any non-terminal lease stamps it** (the `set_template` precedent); RETIRED is excluded from `template_instance_live_uniq` and from `usable()`, so a **replacement can be materialized** (kills stale-content immortality). Physical guest teardown is a separate explicit `destroy_instance_guest` step — fence-checked, confirms `template=1` + `TEMPLATE_TAG`, refuses while linked clones exist, and **refuses `guest_shared`** while any other live instance row (any template) holds the same `(cluster_id, vmid)` (§3.2's shared-guest discipline) — or documented operator debt.
- `delete_template_instance(instance_id, force=False)` — refuses while any **non-terminal** lease references it; `force` severs **terminal** history's `template_instance_id` to NULL (the `delete_node` pattern, audited) then deletes (kills forever-pinned instances). Never touches the guest.
- **Drift repair**: N consecutive clone-source-gone failures against one instance auto-flips **every live instance row on that `(cluster_id, vmid)`** RETIRED (`hold_reason='instance_missing'` on the affected leases; audit breadcrumb) — the ledger reconverges with reality instead of black-holing placements forever.

### 4.5 Legacy env paths

- `BR0KR_VM_CLONE_STORAGE` is **retired**: boot `log.error` if set, value ignored; the deploy runbook **deletes the line from the deploy host's `.env`** (a rolled-back binary must not find it — the rollback re-arm attack).
- `BR0KR_VM_TEMPLATE` and `BR0KR_VM_DISK` **fail closed the moment the registry serves >1 node or >1 cluster**: template-less asks on a multi-node fleet refuse `env_default_multinode` (create-blank) or the daemon holds with `hold_reason='env_template_wrong_cluster'`. This closes the template-less bypass that gutted approach 1. Single-node the deploy host behavior is unchanged.

### 4.6 Queue classification

- `no_reachable_instance` — **HARD** for the whole-ask outcome *only when every candidate's rejection is operator-mutable*. **Mixed-candidate rule** (kills the "one unreachable node disables the queue" regression): if **any** candidate was rejected for a time-mutable reason (`insufficient_*`, `no_capacity`), the ask queues on that reason exactly as today, and `promote_scheduled` re-runs the full search (the parked lease waits on the busy-but-reachable node, never refused for the unreachable one).
- `no_reachable_instance_replicating` — **QUEUEABLE**: a live job covers a `(T, cluster, storage)` the ask could use. Job liveness is re-read **inside the parking transaction** (kills the enqueue race). The parked lease stamps `awaiting_replication_id`.
- **Promoter non-holding set**: the permanent placement codes (`no_reachable_instance`, `storage_unreachable_from_node`, `linked_clone_storage_pinned`, `storage_unbound`) and awaiting-replication waiters join the `('gone','template_forbidden')` continue-without-holding branch in `daemon._promote` **and** `promote_scheduled`'s short-circuit tuple — a parked lease that cannot promote until an external event never holds `node:`/`project:`/`storage:`/`cluster:*` lanes (kills both FIFO-wedge attacks). A queued lease whose reachability broke permanently while parked is actively CAS'd `PENDING→REJECTED` with the placement reason (faster, honest signal; operator action was required anyway).

### 4.7 Declaration reconciliation (rev 2 — continuous, narrow-only)

- **`verify_declarations(cluster_id=None)`** — read-only-against-PVE admin verb shipped **in this arc** (PR-3): for each served node, `GET /nodes/{n}/storage` and reconcile against the declared `storage_node` rows + `pve_name` bindings. **AS SHIPPED (narrowed vs the original spec after the adversarial review, to avoid a false, outage-causing quarantine):** it quarantines **ONLY** a pair PVE reports **explicitly `enabled=0`** (the durable operator off-switch = hard evidence, audited). An **ABSENT** pool (PVE ACL-filters the listing per pool, so absence is ambiguous) and a merely **INACTIVE** pool (`active=0` but enabled — often a transient mount blip) are **reported, never quarantined**; the post-clone assertion (§4.3) stays the hard per-clone tripwire for those. PVE storages with no declared row are informational only; the verb **never widens**. It runs a **two-pass** shape — gather every node's listing FIRST, then reconcile — so a per-cluster ACL gap aborts *before any write* (true all-or-nothing) and a transient per-node read failure is reported under `unreachable_nodes` rather than raising out of the operator verb.
- **ACL prerequisite and graceful degradation:** the GET requires `Datastore.Audit` on `/storage` for `br0kr@pve`. The verb ships regardless; without the ACL it returns `{ok:false, reason:'acl_insufficient', required:'Datastore.Audit on /storage'}` and quarantines nothing (no dedicated fleet stat — `quarantined_reachability_pairs`/`unverified_reachability_pairs` are the standing ledger-side drift signals). The ACL widening is an explicit operator decision (§11 Q4).
- **Cadence:** operator-run on demand, plus an optional leader pass behind `operator_setting verify_declarations_interval_seconds` (default 0 = off) that emits the same report as audit breadcrumbs + a `declaration_drift` fleet stat.
- **Runbook standing rule (added verbatim):** *"If you touch `storage.cfg`, move a template disk, or restrict a storage's nodes list — run `verify_declarations` and update br0kr's declarations before the next lease."* Together with the post-clone assertion (which catches what this verb structurally cannot), silent declaration rot now has both a periodic detector and a per-clone tripwire; correctness no longer has a half-life of one operator forgetting.

## 5. Cross-cluster replication strategy

### 5.1 Trigger model

Replication is a **first-class, explicitly-REQUESTED async job** — `replicate_template(template_id, target_cluster_id, target_storage_id)` (MCP verb, governance-gated on the logical id; dashboard act-as parity) — **never spawned automatically by a lease ask in v1**. Queueing *behind an existing job* is supported (`no_reachable_instance_replicating`); refusals carry `replicable_to` hints so an agent can request the copy itself. Lease-time auto-spawn is a possible later layer once the waiter coupling is proven live (§10).

**Request-time eligibility must simulate the post-copy placement** (kills the unfulfillable-promise attack): refuse `mechanism_unavailable` if no `(node, hypothetical-instance, clone-storage)` triple would exist even after READY under current knobs.

### 5.2 Mechanisms (behind an allowlist knob; shipped in safety order)

1. **`clone_shared`** (intra-cluster, first, zero unverified PVE behavior): on the **source instance's node**, full-clone T to a target storage **reachable from that node** (`reach(source.node, target)` — evaluable now that instances carry `node_id`); fence, **post-copy placement assertion** (§5.3), `make_template`, finalize. The resulting instance is **hosted on the source node** — documented honestly; the follow-up "offline config-migrate to the target node" is a live-validation-checklist item, not a v1 dependency. This alone makes "debian12 reachable from node-b-in-lab1" true by copying it onto OMV *once cross-node clone (or the config-migrate) is verified*; until then it fans out per-pool for the hosting node and multi-node service arrives with the knob flip.
2. **`rebuild_source`** (cross-cluster, provenance-gated): replay `download_image → build_template_vm → make_template` on a target-cluster node **chosen by `reach(node, target_storage)`** (never first-node — kills the 683-690 assumption at its root). Content-identical by sha256 **to the recorded source** — which is why the gate is two-sided (rev 2):
   - **Refuses provenance-less templates** (`source_not_replicable`) rather than minting an agent-less replica — this solves the provenance-**less** half only, and the doc no longer claims more.
   - **Refuses hand-modified built templates** (`source_hand_modified`) when `template.source_dirty` is set. The concrete named scenario: a template built from `source_url`+`sha256` whose guest the operator later hand-fixed in PVE — e.g. installing qemu-guest-agent per the standing rule — is rebuild-*eligible* by provenance but a rebuild would silently reproduce the pristine image **without the fix**, giving one logical id per-cluster behavioral divergence. The `mark_template_source_dirty(template_id)` operator verb (audited; cleared automatically by the next `mark_ready` build, or explicitly) is the attestation; the runbook standing rule is *"any hand modification of a built template's guest ⇒ mark it dirty in the same sitting."* An audited `force=true` exists for the operator who knows the divergence is acceptable. Residual (drift-by-assertion, sacrifice §10.7) is now named, bounded, and visible per-instance via `origin`/provenance in the instances block.

   Hand-baked templates (debian12/9900) cross clusters only via operator `vzdump`/restore + `register_template_instance(origin='manual')` — which now carries full validation and the registration-time tag check (§4.4).
3. **PDM-based move: OUT** (§2.1, §10).

### 5.3 Job lifecycle, capacity, and the copied-completely saga doctrine

`REQUESTED → COPYING → CONVERTING → READY | FAILED (+RECLAIMING)`, guarded-CAS transitions in a new `replication.py` (build.py's shape):

- **Claim**: CAS `REQUESTED→COPYING`; the twin `template_instance` row (`instance_state='REPLICATING'`, **vmid NULL** — the NOT-NULL contradiction from the middle design is resolved: vmid is nullable, `READY ⇒ vmid NOT NULL` by CHECK) inserts in the same CTE so duplicates block at both indexes and refusals can say "replicating".
- **vmid mint**: target cluster's `nextid`, stamped **with `node_id` in one CAS** under `replication_cluster_vmid` (0029 prong 2); `UniqueViolation` = clean fresh-nextid retry. The **unstamped-reclaim branch is specified**: vmid NULL ⇒ nothing to destroy ⇒ one CTE flips job FAILED + instance FAILED + stamps `guest_settled_at` + settles the reservation by key (mirrors reaper's vmid-None branch).
- **Fencing**: the transient guest cannot be fenced *in* the clone call (PVE clone takes no tags) — so: an **immediate guarded post-clone config POST** stamps `br0kr-repl-<id>` (read tags first; proceed only if marker-present-and-unfenced, mirroring `clone_orphan_decision`), and `lease.clone_orphan_reclaimable`'s evidence is **extended to spare any vmid stamped by an active `template_replication` or REPLICATING instance row in the swept cluster** (kills the sweep-eats-the-copy attack). `parse_repl_fence == job_id` is re-checked immediately before `make_template`'s POST (kills the vmid-reuse template-conversion attack).
- **Post-copy placement assertion (rev 2):** after the copy lands and the fence is stamped, before `make_template`, the same disk-location assertion as §4.3 runs against the guest's config — volid storage name must equal `target_storage_id`'s effective `pve_name`. Mismatch ⇒ CAS job FAILED (`landed_wrong_pool`), reclaim the guest, quarantine the `(node, storage)` pair. A replication can therefore never mint a catalog instance whose recorded pool is a lie.
- **Convert/finalize**: `make_template` (template=1 **before** the `TEMPLATE_TAG` marker), then one CTE: job READY + instance READY (+ vmid), then fence strip; the **confirmed** strip stamps `guest_settled_at`. **A READY job whose guest still carries the fence is repairable state**: an idempotent leader finalize-retry step re-drives the strip (the build path's "tolerated finalize failure" stops being tolerated the moment a sweep can see the fence) and stamps `guest_settled_at` on success.
- **Reservation** (the storage-byte floor during the copy): a reservation **lease** through `admit()` — idem key `br0kr-repl-<id>`, `storage_id = target`, `req_disk_gb = declared size_gb`, and (rev 2, precedent cited instead of asserted) **the exact column shape the migration saga's `br0kr-mig-` reservation already admits today**: `project_id = NULL`, the same integer validator-minimum `req_cpu`/`req_mem` token values migration passes — **no novel fractional values are introduced** (the earlier "0.1 cpu / 16MB" is dropped; whatever integers the existing validators accept for the mig reservation are reused verbatim). Every downstream reader is enumerated and already prefix-aware or prefix-extended: `list_admitted`'s reserved-prefix exclusion (lease.py:583-589) gains `br0kr-repl-` in the same expression; the reaper's vmid-None branch settles it cleanly; dashboard/`list_leases` filter it under the same reserved-prefix rule as mig reservations. A **pinned hermetic parity test** asserts a `br0kr-repl-` reservation admits and settles byte-identically to a `br0kr-mig-` one. TTL `≥ 2× BR0KR_REPL_STALE_SECONDS`, **re-heartbeated on every progress poll**, and a lapse (`heartbeat → None`) forces the job to FAILED/reclaim **before any READY transition** — the `migration._actuate` `reservation_lost` mirror, adopted verbatim this time. Settled **by deterministic key** on every terminal path; held for the whole copy (S07: never settle mid-copy).
- **Interrupt/stall/retry**: `upid` write-once + re-attach; heartbeat `updated_at`; stale cutoff `BR0KR_REPL_STALE_SECONDS` (default 7200) **plus a hard wall-clock cap** (`created_at`-based) that FAILs a zero-progress-while-polling job (`wall_time_exceeded`) — heartbeat freshness measures "leader polling", not "copy progressing" (the wedge attack); exclusive CAS-to-RECLAIMING that a concurrent completion wins; destroy-first on the **stamped** node; **`fence_mismatch` from the destroyer = guest-settled** (the vmid provably changed hands; clear stamp, stamp `guest_settled_at`, FAILED/retry — kills the RECLAIMING-forever wedge); never reclaim REQUESTED; `attempts+1` up to `max_attempts=3`; **cross-job cooldown** keyed on `(template, target)` after a terminal FAILED (`replication_cooldown` refusal) so a persistently failing target can't be hammered.
- **Escape hatches** (the build arc's S04/F4 lesson, not dropped this time): `cancel_replication` (requester/operator, REQUESTED-only CAS→FAILED, frees the one-active slot + quota reserve, no teardown needed) and `force_fail_replication` (operator, audited, wedged CLAIMED/RECLAIMING jobs, logs orphan-risk with the fence handle).
- **Catalog-collision path**: on `template_instance_live_uniq` conflict post-conversion, **adopt-or-destroy** — if the winning instance is the same vmid, CAS READY (idempotent); else destroy own guest and FAIL with `instance_exists`, and the waiter sweep treats `instance_exists` as "do NOT early-reject; the promoter will admit you next tick" (kills the reject-at-the-moment-of-success attack).
- **Quota permanence and the single-debit rule (rev 2 — the double-count/handoff ambiguity resolved):** tenant-requested replicas' READY instances **join `project_template_disk_used`** (sum term over instances attributable via `replication.project_id`) so the charge survives settle (kills the free-fan-out attack). Bound quota rows' derived headroom subtracts template bytes under **exactly one debit per byte at any moment**:
  - **In-flight copy** → floored by the reservation lease's `req_disk_gb` via `CAPACITY_STATES` (the existing `_STORAGE_AVAIL` machinery). The read-side term does **not** count active jobs — that was the double-count.
  - **READY instance** → floored by the read-side subtraction Σ `size_gb` over READY instances bound to the pool (a WHERE-join inside the query `admit()` already runs; no new debited scope, no lock-grammar change).
  - **Handoff ordering:** the `mark_ready` CTE commits instance READY **first**; the reservation settle-by-key runs strictly **after** that commit. The seconds-wide overlap counts the bytes twice — deliberately **conservative** (a marginal admit refuses briefly), never an undercount; the physical floor can only be over-protected during handoff, never eroded.
  - **NULL `size_gb` handling (no more silent zero):** `size_gb` is REQUIRED on `register_template_instance` and `bind_instance_placement` and stamped by every replication, so only pre-existing unbound seeds can lack it — and the `register_node` unbound-gate already forces those through `bind` (which requires it) before any multi-node cluster exists. Until then, NULL-sized rows subtract nothing but are counted in an `unsized_instances` fleet stat + boot warning — flagged, single-node-only, and structurally cured by the same verb that cures unboundness.
  Jobs also **preflight** target headroom (`target_storage_insufficient`) instead of failing reactively.

### 5.4 Waiter coupling (level-triggered, honest reasons)

A per-tick leader sweep over PENDING leases with `awaiting_replication_id`:

- Job **FAILED** → CAS `PENDING→REJECTED`, `released_reason='replication_failed:<sub-reason>'` (+ `replication_id` in the refusal detail). No full-deadline wait, no `queue_timeout` lie. Level-triggered, so late attachers and races are covered.
- Job **READY but still no triple after M promote passes** → reject `replication_completed_unreachable` with the `tried[]` trace (honest fast failure over a silent second wait).
- A waiter that hits `queue_deadline` while the job is still live gets `released_reason='queue_timeout_awaiting_replication'` (distinguishable), and the parking response surfaces the job's age + stale cutoff so agents size `max_wait_seconds` sanely (the 3600s-default-vs-7200s-cutoff contradiction is called out in docs and the parking path floors nothing silently).

## 6. Invariant preservation

1. **`admit()` sole authority (I1)**: reachability is a fail-closed **read** under the *already-held* node advisory lock in the template step of `admission._locked_fit`, which `admit()` and `promote_pinned` share; it debits nothing and adds no scope. The only new capacity flow — the replication reservation — goes **through `admit()` itself** (deterministic reserved idem key, dedicated non-autocommit READ-COMMITTED connection in the leader tick, settle-by-key, heartbeat + lapse-abort, column shape lifted verbatim from the mig reservation): the migration saga's recipe with zero new race-critical SQL. Clone-storage resolution runs **only for `template_id IS NOT NULL` asks**, with a pinned hermetic test that a `br0kr-mig-`/`br0kr-repl-` reservation admit is unaffected (kills the migration-reservation regression).
2. **Ordered advisory locks / scope strings (I5)**: `scope_keys()`'s single sorted list, the `'storage:{id}'` string, and `_queue_block_keys` are byte-identical — no mixed-version rollout window. The `storage_pool_uniq` index (not a lock change) closes the aliased-rows double-sell.
3. **Per-cluster vmid fence (I2)**: `lease_cluster_vmid_uniq` and `begin_provisioning`'s one-CAS stamp are untouched (no new lease state ⇒ no 0004/0017 re-issue). Instance and job vmids get their own per-cluster partial unique indexes; the residual cross-namespace failover-overlap collision is arbitrated by PVE-create failure + fences, and **both** loser paths are specified as clean (`VmidContended` retry lease-side; `fence_mismatch`-as-settled job-side) — churn, never a wrong destroy, never a wedge.
4. **Storage quota debit (I3)**: `_STORAGE_AVAIL`, `CAPACITY_STATES`, the pairing validations, and every live lease's debit are unchanged (additive nullable columns). The new coupling is one-directional and *tightening*: a debited bound row must also be the physical pool (§4.2), the post-clone assertion verifies PVE agreed (§4.3), and bound-pool headroom now also sees template bytes under the single-debit rule (§5.3).
5. **No-orphan (I4), two-sided for the new artifact class**: ledger-first ordering (job + instance rows before any guest; vmid+node stamped together); fence from the earliest possible moment with the unfenced window covered by the **extended** clone-orphan evidence; every destroyer through `_stop_then_fenced_delete` with fresh reads both sides; the sweep's repl-fence rule is **positive-FAILED-evidence only** (§6.6 below); lease clones of new instances inherit `TEMPLATE_TAG` exactly as today. Hand/manual instances: tags verified at **registration** (§4.4) AND the daemon re-reads them before the first clone (`template_untagged`) — the register-path orphan class is caught at row-creation and again at clone #1, never crash #1. The assertion-mismatch release path uses the standard fenced release (guest is fenced by then), so it mints no orphans either.
6. **Sweep rules for `br0kr-repl-<id>`** (the critical finding, pinned): destroy **only** on job `FAILED` (never READY — READY is success-terminal and the guest is the catalog template; never absent — the only prunable jobs carry `guest_settled_at`, so an absent-row fence is provably foreign ledger: spare + warn; no watermark needed under spare-by-default); the sweep-path destroyer **refuses `template=1`** (template-deletion authority belongs solely to the RECLAIMING-claimed ledger path and the explicit destroy verb, which itself carries the `guest_shared` refcount guard); a repl fence on a vmid ≠ the job's stamped vmid is refused and alerted.
7. **Idempotency (I6)** and **MCP contract (I7)**: ask columns unchanged; broker-resolved columns excluded from `_same_ask` (and the daemon's late stamp resolves identically by purity); all new codes dict-not-raise, docstring-enumerated, explicitly classified (§4.6).

## 7. Failure-mode observability (first-class, both channels)

**Shared machinery.** (a) A **dedicated, parameterized `DenialLog` instance for placement refusals — shipped in the same PR as the first refusal code, not deferred**: key `(surface, action, reason, template_id, project_id)` (project_id is **in** the key so two tenants' refusals never coalesce into one mis-attributed row — adversarial review), 60s window, own ceiling (~100/window), writing `operator_audit` rows with the new outcome `'refused'`; it extends `DenialLog` with caller-supplied key fields, and the written row carries the **reserving caller's own** params (not a shared per-key buffer, which would race a concurrent same-key event); the auth `_denials` instances and their 200/60s intrusion-signal ceiling are never touched. (b) `audit.redact` preserves node/storage/template ids and reason codes; params carry the ask + trace, never results/credentials; writes are post-decision, best-effort, on the tool's own connection, never inside `admit()`'s txn. (c) Log extras use redaction-safe keys **only** (`lease_state`/`job_state`/`candidate_reasons`/`guest_ip` — never `state`, `region`, anything containing `address`/`dsn`/`token`); decision traces are INFO (0022's hot log knob is daemon-only; audit is the durable channel regardless of container `LOG_LEVEL`), with a per-`(idem_key, reason)` in-process log coalescer (first + every Nth). (d) **`daemon._publish_health` is changed to iterate `dataclasses.fields(TickSummary)`** with a test asserting every counter reaches `/metrics` — the "auto-rendered" claim is currently false in code (two hardcoded literals at daemon.py:963-977). (e) Gateway-side refusal **counts** reach `/metrics` via the leader's per-scrape ledger query over recent `outcome='refused'` rows by reason (the leases-by-state pattern) — the daemon-process TickSummary alone cannot see gateway refusals. (f) **Dashboard is wired in**: the shared refusal writer fires from mcp_server, gateway, **and dashboard/actas** paths, triggered only on the **final** response (`admitted=false AND queued=false`) so queued-then-promoted asks are never falsely audited as refused.

## 10. Explicit sacrifices / non-goals

1. **No lease-time auto-replication in v1** — a missing instance is a clean refusal (with a `replicable_to` remedy) or a queue behind an *explicitly requested* job. Auto-spawn is a candidate later layer, gated on the waiter coupling proving out live.
2. **No widening PVE probing in this arc** — reachability is operator-declared; a wrong declaration causes refusals (fail-closed) or a would-be-wrong placement that the provision guard holds. **The over-declaration residual is now runtime-closed, not merely narrowed** (rev 2): a maliciously-plausible over-declaration onto dir-type storage can still cause PVE to *transiently* land bytes locally — but the mandatory post-clone disk-location assertion (§4.3, §5.3) detects it before the lease ever goes ACTIVE (or the instance ever converts), destroys the guest, audits with a distinct code, and quarantines the declaration. The residual sacrifice is precisely: *a transient wrong-pool write and a loudly-failed lease*, never a silently-ACTIVE wrong placement. `verify_declarations` (narrow-only) plus the pair verified/quarantined lifecycle are the standing detectors; widening discovery, when it comes, remains narrow-only by pre-committed contract.
3. **Hand-baked templates don't cross clusters automatically** — debian12/9900 has no provenance and a rebuild would lose in-guest baking (qemu-guest-agent standing rule); the sanctioned path is `vzdump`/restore + `register_template_instance` (now fully validated + tag-checked). PDM template moves are out entirely.
4. **v1 instance availability is per-hosting-node** — cross-node intra-cluster service arrives only with the verified `cross_node_clone` knob (or the config-migrate step); until then multi-node service means per-pool fan-out via `clone_shared` + the knob flip. Strictly safer than today.
5. **Operator-initiated replica disk is not a debited quota scope** — it *is* subtracted read-side from bound pools' headroom (READY instances; in-flight copies via the reservation debit — one debit per byte, §5.3) and charged to tenant projects when tenant-requested, but no new advisory-lock scope exists for template bytes. Documented, visible in fleet stats (`unsized_instances` covers the only rows that can escape the term, and binding cures them).
6. **One physical pool spanning clusters = split quota rows** whose `total_gb` the operator apportions; the ledger does not model a cross-cluster shared bucket.
7. **Content identity across instances is provenance-level, not attested** — `origin`/`source_sha256`/`created_at`/`source_dirty` are surfaced; manual instances are drift-by-assertion, named as such in the instances block. The concrete named case (rev 2): a **built template later hand-modified in-guest** (e.g. qemu-guest-agent installed by hand) diverges from its recorded source; `rebuild_source` refuses it once the operator marks it dirty, but the marking itself is operator discipline (runbook standing rule) — br0kr cannot detect an in-guest hand edit. That detection gap is the sacrifice; the silent-rebuild-of-stale-content path is not.
8. **Linked clones remain pinned** to the instance's storage and hosting node (PVE physics).
9. **First-copy latency is a feature-shaped cost**: a queue behind a replication is bounded by the caller's `max_wait_seconds`, and the parking response says so with the job's age.
10. **Terminal replication history is prunable, not immortal** — `prune_replications` (settled-only, breadcrumbs retained in `operator_audit`) trades perfect in-table job history for decommissionable clusters; the audit trail remains the durable record (0024 doctrine).
11. Semi-permanent/pinned leases, per-node storage capacity accounting, and the cloud-burst tier remain out of scope for this arc.
12. **Cross-node pick is single-shot, not backtracking (fail-closed over-refusal)** — `resolve_placement` resolves clone-storage for the *single* top-ranked usable instance and, if that resolution refuses (linked-clone-pinned, or a source/ask pool that doesn't reach a node), returns the refusal WITHOUT trying a sibling usable instance that would resolve. Under `cross_node_clone` ON, multiple usable instances per (template, node) become normal (a node-local copy plus cross-node shared replicas), so a **servable** ask can be **over-refused** when the top pick is unresolvable while a sibling would place. It is strictly fail-closed (never a wrong placement, no lockstep break — admit refuses up front so nothing is stamped), and it is **untriggered by the one-instance-per-node topology PR-7 deploys**; it bites only richer multi-replica fleets. Related: the deterministic lowest-id tiebreak is registry-blind, so it can pick a cross-node instance whose source node no daemon serves (→ the lease is HELD `source_node_unroutable` and bounded-auto-releases after 60 re-checks) even when a routable sibling exists. **Follow-up** (a later PR): make `resolve_placement` iterate its ORDER-BY candidates and take the first whose `_resolve_clone_storage` returns ok (deterministic, keeps admit/recheck lockstep since recheck still evaluates only the *stamped* instance), and/or surface a fleet stat counting `source_node_unroutable` holds per instance so the operator retires/rebinds an unroutable-source replica. Surfaced by the PR-7 Fable re-verify (lockstep + sql + actuation lenses).
13. **Node/cluster-drift is closed at the GATE, with residual source-side hardening as follow-ups** — the cross-node widening trusts a `template_instance`'s `node_id` to point at a node still in the instance's cluster (and at the physical host its config lives on). The **root-cause backstop** is now gate-side: `_USABLE_INSTANCE_PICK`'s xnode branch + `recheck_instance` require the source node's current `node.cluster_id = ti.cluster_id` (fail-closed against any drift path). `admin.set_node` (cluster repoint) and `admin.delete_node` refuse `node_has_instances` while a live instance is hosted. **Residual follow-ups** (all fail-closed at the gate today, so none is a live safety hole): (a) a REQUESTED `template_replication` job whose `target_node_id` is later repointed — the twin is claimed with the job's captured `(target_cluster_id, target_node_id)` and the gate then refuses it; the clean fix is a claim-side revalidation `(SELECT cluster_id FROM node WHERE id = target_node_id) = target_cluster_id` in `replication._claim`, and/or extending the set_node/delete_node guards to non-terminal `template_replication.target_node_id` rows (mirroring the `*_has_replications` decommission pre-checks). (b) a **`pve_node` value change** on a node hosting live instances (a legitimate rename vs a repoint to a different physical host is operator-adjudicable) — emit a WARNING; a hard refuse would break renames. (c) the set_node check-then-act race vs `bind_instance_placement`/`_claim` is subsumed by the gate-side coherence check (cross-node) and the pick's existing `ti.cluster_id = node's-cluster` scoping (node-local). A round-4 re-verify closed one more at the gate — a **SEVERED bound instance** (`node_id` NULLed by delete's ON DELETE SET NULL while `storage_id` stays set + READY) slipped through the *seed* disjunct as if it were a genuine unbound seed and would be cloned onto the wrong node; the seed disjunct on both the pick and `recheck_instance` now also requires `storage_id IS NULL` (a genuine seed has both NULL; a severed bound instance uniquely has node NULL + storage set), so it is excluded (harness Q) — this closes pre-existing severances + the delete race, not just new severances (the `delete_node` guard). **Two PRE-EXISTING `set_node` gaps** (NOT introduced by cross_node_clone — they affect node-local placement and predate this arc) remain as a separate hardening follow-up: (d) a `set_node` cluster repoint leaves the node's `storage_node` reachability rows intact (they cascade only on node DELETE, 0031), so a subsequent node-LOCAL full-clone with an ask pool trusts a now-stale `(pool, node)` reach row — with a same-`pve_name` pool in the destination cluster (legal per `storage_pool_uniq`) this could land bytes on the destination cluster's pool while the quota debits the source cluster's pool (a cross-cluster debit-vs-placement — exotic, needs the repoint + a name collision + a rebind). Fix: prune/refuse `storage_node` rows on a cluster repoint, and/or add an ask-pool-cluster == placement-node-cluster check to `_resolve_clone_storage` (one read in the shared helper, lockstep). (e) `set_node` moving a node INTO a cluster bypasses `create_node`'s `cluster_has_unbound_instances` destination guard (can strand a single-node cluster's unbound seed → fail-closed availability outage). Fix: mirror the destination-side two-probe check in set_node's repoint branch. Surfaced by the PR-7 round-3/round-4 re-verifies.
14. **Network reachability: VERIFIED (PR-A, 0038) then REWRITTEN (PR-B, 0039) — both landed** — the placement gate treats the template's NIC bridge as a fail-closed placement dimension exactly like storage. **PR-A (0038)** admitted a cross-node clone only when the placement node was DECLARED to present the template's bridge, else refused `template_bridge_undeclared`/`network_unreachable_from_node` at admit (the network twin of `storage_unreachable`); its residual was that it did NOT REWRITE `net0` — a cross-node clone kept the template's baked bridge verbatim, so it required the SAME bridge NAME on the placement node (the heterogeneous-node wall: node-a `vmbr402` vs node-b `vmbr0`). **PR-B (0039)** closes that: it RE-KEYS the reachability onto a fleet-global `logical_network` IDENTITY (`network_node(node, logical_network) → bridge`, superseding the raw `node_bridge`/`required_bridge`, auto-backfilled + deprecated one release) and the reconciler REWRITES `net0`'s `bridge=` token to the placement node's OWN bridge for the template's logical net, in the SAME configure call as the fence. The wrong-L2 footgun — rewriting to a same-named bridge that is a DIFFERENT L2 on another node — is closed BY CONSTRUCTION: the key is the identity, never a raw name, and each node independently declares which of its bridges realises the net. `_resolve_network` (shared by admit + provision, EXACT lockstep) resolves `(node, logical net) → target bridge`; the daemon threads `target_bridge` — the twin of `--target-storage`, and `pdm.py` already plumbs Proxmox's `--target-bridge` for the cross-cluster PDM path (harness/unit-validated only; the homelab has no second cluster to live-verify against). **PR-A's fail-safe residual is now CLOSED**: the post-clone assertion re-checks the bridge `net0` was actually rewritten TO (not a separately-declared `required_bridge`), so `net0 == the asserted bridge` by construction — a mismatch can no longer exist. On a lying per-node declaration (the declared bridge absent) the assertion still releases the fenced guest + quarantines the `(node, logical net)` pair. **STILL DEFERRED (design-decided, Q3 = keep PR-B tight):** the fleet-wide `verify_declarations` NETWORK arm (reconcile every `network_node` vs each node's live bridge list) — the per-clone net0 assertion remains the standing tripwire. SDN remains deliberately avoided — for routed-reachability workloads it is additive per-cluster maintenance with no shared cross-cluster identity, so it never REPLACES the broker map. `detect_template_bridge` is now a READ-ONLY advisory (reports the baked bridge + current identity to help an operator map a template to a logical net; the identity is an operator CHOICE the verb can't infer). Live-verifiable as the full boot+IP on node-b (logical net `lan`: node-a→`vmbr402`, node-b→`vmbr0`; a cross-node lease to node-b clones, rewrites `net0` `vmbr402`→`vmbr0`, boots, gets a 192.168.1.x IP). Surfaced + decided in the PR-7 node-agnostic-bridge design conversation. **KNOWN LIMITATION — net0 ONLY (single-NIC scope):** the rewrite + assertion cover `net0` only (`read_guest_net_config` reads `dev="net0"`; the gate does not model a template's NIC count). A MULTI-NIC template's `net1+` keep their baked bridges across nodes exactly as before PR-A — so `net1` on a placement node that lacks that bridge NAME fails LOUD at `qm start` (fail-safe), but `net1` on a placement node that presents a same-NAMED bridge on a DIFFERENT L2 boots on the wrong network (silent — the pre-existing fail-open the net0 rewrite does NOT extend to). The `(node, logical net)` `verified` stamp is `net0`-scoped and does not attest `net1+`. This is fail-safe for the single-NIC fleet (the broker's own template-build + cloud-init path produces single-NIC templates; the live catalog is single-NIC); multi-NIC support (a per-NIC logical-net map: `net0→lanA`, `net1→lanB`) is a clean future PR. **PR-B fable-round hardening (this arc):** `quarantine_network_pair` now guards against a `delete_logical_network` mid-provision (the defensive INSERT would FK-abort the daemon tick — a new-in-0039 crash the raw-bridge twin lacked); `mark_network_verified` is keyed on the proven bridge (a mid-provision re-point can't inherit an unearned `verified_at`); `admin.delete_network_node` restores single-pair un-declaration (0038's declarative `set_node_bridges` gave it for free); `rewrite_net_bridge` substitutes a malformed empty `bridge=` rather than appending a duplicate key.
